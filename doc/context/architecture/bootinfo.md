# E820 交接与引导内存布局（第 7 章）

对应目录中的“获取物理地址空间信息”和“操作系统引导加载阶段的内存空间划分”。
原版 `code/c07/7-2/物理平台/bootloader/loader.asm` 提供 BIOS E820 调用路径，
本地实现继续保留显式容量、独立缓冲和 Rust 校验；不照搬失败后继续使用半张表的流程。
源码：`loader.asm` 采集，`bootinfo.rs` 校验并复制，`memory.rs` 建立分配器元数据。

## Loader 怎样完成采集

第一次 EBX=0，后续原样传递 BIOS 返回的续传令牌；它不是条目下标或地址。
每轮重新设置 EAX=0xe820、EDX=SMAP、ECX=24、ES:DI=0000:5300，
使用独立 24 字节 scratch，避免把扩展属性写入相邻的 20 字节条目。
调用前清 scratch 并将扩展属性初始化为 1，返回后只接受完整的 20/24 字节结果。
保存 DS/ES/DI，恢复时不改变返回 CF；成功结果还必须满足 EAX=SMAP。

20 字节结果直接复制基础字段；24 字节结果按以下规则规范为 20 字节：

- 属性 bit0 清零的旧式禁用条目长度归零，保留槽位但不作为 RAM 使用。
- 其他属性位非零时，类型保守改为 reserved，避免把错误日志等特殊区间交给分配器。
- 未知类型保留原值，内核只将 type=1 作为普通 RAM。

每次成功返回都占一个槽位，包括零长度条目，因此不会因固件反复返回忽略条目而无限循环。
最多保存 32 条；满表后仍可在独立 scratch 进行一次终止查询，若返回额外有效结果则失败，
不静默截断。EBX=0 表示结束；已有条目后的 CF=1 也按规范接受为结束，首轮 CF=1 则失败。
CF 终止不携带额外结果，本接口无法区分固件的合法结束与同样以 CF 表示的中途错误。

规则依据 [ACPI 6.6 第 15 章](https://uefi.org/specs/ACPI/6.6/15_System_Address_Map_Interfaces.html)。
当前规范把 bit0 定为必须为 1 的保留位；清零忽略兼容较早的 enabled 语义。

## 固定交接 ABI v1

`0x4ff0` 起为 16 字节小端头，后接 `[0x5000,0x5280)` 的 32×20 字节数组。
该地址原来的单独 u16 数量协议已替换；Loader 与 Kernel 必须一起重建。

| 头内偏移 | 字段 | 条件 |
| --- | --- | --- |
| 0 | u32 magic | 0x30323845，即字节 E820 |
| 4 | u16 version | 1 |
| 6 | u16 entry_size | 20 |
| 8 | u16 count | 1..32，包括零长度槽位 |
| 10 | u16 capacity | 32 |
| 12 | u32 flags | 1 表示 complete；其他值拒绝 |

Loader 先清头与数组，仅在完整采集后最后写 complete。Rust 先验头、再按数量复制条目，
因此失败遗留的数据或旧版本头不会被直接用于分配。packed 条目仍为 base:u64、length:u64、type:u32。

Rust 接受无序、零长度和未知类型，检查每个 base+length 的溢出，拒绝任意两个非空区间重叠，
包括 RAM 覆盖 reserved/ACPI/NVS 的情况。检查在元数据写入前完成；零长度不计入物理地址上界。
本节选择拒绝重叠，未实现通用固件修复器的拆分与类型优先级覆盖。

## 布局怎样受约束

NASM 编译时检查头/数组/scratch 互不覆盖，scratch 必须位于约定的早期栈区下方。
VBE 枚举写入 256 字节 ModeInfo 前检查末端不跨 `0x10000`，保护正在执行的 Loader。
构建器继续限制 Loader 小于 64 KiB；链接器限制内核在初始 10 MiB RAM 直映内。

Rust 按完整 E820 表复核 `[0x4ff0,0x5318)` 的交接缓冲、`[0x6000,0x10000)` 的
栈/Boot/读盘/VBE 槽位、`[0x10000,0x20000)` 的 Loader 槽位和 `[0x90000,0x93000)` 的
过渡页表槽位都被单个 type=1 区间覆盖。内存模块再检查整个内核+BSS+元数据范围属于 RAM，
而非只检查 `_end` 后面的元数据尾部。首次分配仍保留 `[0,end_of_struct)` 覆盖的全部 2 MiB 页。

这些是 Rust 接管后的复核，不能追溯防止 BIOS/Loader 已经完成的写入；早期栈也没有硬件 guard。
这不是可适应任意 EBDA/碎片内存的动态布局器，其他固件布局可能被明确拒绝。

smoke 在内核第一条指令前导出完整 656 字节交接区，核对头字段，并逐条与内核打印结果比对。
`memory-check` 追加局部构造的头/溢出/重叠/无序/保留边界检查，不覆盖真实固件表。
模拟器实际运行不代表已测试 BIOS 的所有 20/24 字节、CF、超容量及扩展属性分支；
具体证据见 [验证记录](../development/validation.md)，布局总表见 [启动](boot.md)。
