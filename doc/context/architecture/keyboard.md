# 键盘中断与扫描码捕获

对应父目录原版 `code/c04/4-10/kernel/interrupt.c` 的 IRQ1/0x60 实验。
源码 `src/kernel/keyboard.rs`，IRQ 分发在 `interrupt.rs`，PIC 屏蔽接口在 `interrupt/pic.rs`。
本节捕获控制器输出的扫描码字节，不做 ASCII、组合键、命令行或完整扫描码序列解析。

## 从按键到主循环

```text
按下/松开键 → PS/2 键盘发 set2 字节 → 8042 翻译为 set1，输出缓冲置满
  → 控制器 IRQ1 → PIC 向量 0x21/ISR1 → CPU IST3 → irq_dispatch
  → keyboard::on_interrupt：检查 0x64，读取 0x60，入队
  → PIC specific EOI，确认 ISR1 清零 → IRETQ
  → keyboard::run：IF=0 下取队列字节并显示 → 队列空时 STI/HLT/CLI 等待
```

读取 0x60 消费设备数据，让控制器撤销请求；EOI 结束 PIC 的服务状态。
两个动作缺一不可：只 EOI 不取字节可能阻止后续输入形成新的边沿，只取字节不 EOI 会阻塞 PIC。
区别于原版，无关 IRQ 不读 0x60；IRQ 中不做慢速绘字，主循环负责日志。

## 初始化前提与协议

只支持本节传统 PC 的第一 PS/2 端口；不探测 ACPI 8042 标志，不提供 USB 键盘驱动。
调用顺序为内存完成 → PIC 初始化/时钟演示完成、全屏蔽 IF=0 → keyboard::init。

0x64 读状态、写控制器命令；0x60 读输出、写数据/参数。状态 bit0=输出满、bit1=输入满、
bit5=辅助端口数据、bit6/7=传输错误。写之前等输入空，读之前等输出满，初始化轮询预算
100,000 次，属于有限循环而非毫秒计时；超限 panic，不声称任意机器的时序兼容。

初始化禁用两端口、最多消费 64 字节旧输出，命令 0x20 读配置；0x60 写配置。
配置 bit6 开 set2→set1 翻译、bit5 保持第二端口禁用、bit4 清零允许第一端口时钟，
bit0/1 暂时关闭控制器 IRQ。0xae 开第一端口后，向键盘依次发 F5、F0、02、F4，
暂停扫描、选择 set2、恢复扫描；每字节消费 FA ACK，FE RESEND 最多重试 3 次。
最后只置配置 bit0 开控制器 IRQ1，再将 PIC 主片 IMR 改为 0xfd。
命令 ACK 在关中断、PIC 屏蔽时消费，不交给普通扫描码队列；第二端口和 IRQ12 保持禁用。

这是与原版依赖 BIOS 状态的差异；没有重置/自检、LED、热插拔、完整错误恢复或运行中命令事务。
初始化期间按键/其他来源若打乱应答流，明确停止，不把未知应答继续当配置使用。

## 有限队列和并发边界

64 字节环形队列记录 head/length，满则丢新字节并计数，已有字节顺序不变。
中断检查输出满后取一个字节；空请求、辅助端口或错误字节记录 errors，错误数据不入队。
主流程打印丢失/错误计数后清零。扫描码不被解释或丢弃前缀：set1 中 a 按下/松开为 1e/9e，
扩展键可能有 E0/E1 等多字节，字节流不等于字符流。丢字节后的完整序列恢复留待后续解析器处理。

所有队列访问仅在单核 IF=0 下发生，IRQ 不嵌套、NMI 不访问队列；引用在等待前结束。
arch 的等待汇编保留编译器内存屏障，中断返回后重新读取队列。无堆、无锁、无 SMP 支持。

## 普通交互与自动验证

普通镜像保持接收循环，`kernel_keyboard_wait` 是 STI/HLT 等待入口，不是最终关中断停机。
普通、memory-check、irq-check 的 smoke 在此入口断点退出，证明初始化到达接收边界，
不将这条检查当作真实按键交付。故障演示仍在 ready 之后触发，走 kernel_halt。

`keyboard-check` 先用局部队列验证 FIFO、环绕和满队列丢新字节；宿主 scripts/smoke.py
读取本次 Bochs RFB 监听端口，用 RFB 3.3 无认证握手发送 a/b 的 KeyEvent 按下/松开。
逐个等待内核打印 1e/9e/30/b0；内核也核对顺序及零丢失/错误，随后全屏蔽并到达 kernel_halt。
这些数据经过模拟键盘/8042/PIC/IRQ1，没有向内核队列塞字节，也没有用软件 INT 代替设备请求。
VNC 不请求画面，不改变现有 32 bpp 显示限制；仍不能证明 GUI 可视效果或真机输入。
命令见 [构建](../development/build.md)，实际证据见 [验证](../development/validation.md)。
