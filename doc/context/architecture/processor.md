# 处理器体系结构（第 6 章）

原版对应 `code/c06/6-1`，以及第 6 章的基础功能与新特性、地址空间、实模式、
保护模式、IA-32e 模式五部分。与 `code/c05/5-3` 逐文件比较：`main.c`、Loader、
任务与内存逻辑相同，入口汇编只有空白差异，另有模拟器配置差异。
因此本章主要解释已经使用的机制，不把后续章的 CPU 信息采集、引导增强或调度器提前实现。
本项目新增 `src/kernel/processor.rs`，只读核对启动模式，并在原模式切换处补充注释。

## 从指令编码到硬件能力

`BITS 16/32`、`.code64` 告诉汇编器怎样编码指令；它们不会切换 CPU。
CPU 根据控制寄存器、EFER 和当前代码段的隐藏属性解释这些字节。
所以在错误模式下跳入一段“64 位汇编”，不能自动完成模式切换。

同样，64 位通用寄存器不表示有完整 64 位物理地址空间，也不表示全部 RAM 已映射。
CPU 的支持能力、软件启用状态、实际存在的内存与页表覆盖范围是不同层次。
现有 Loader 用 CPUID 扩展叶的 LM 位判断 long mode 支持；用户入口还核对
Intel/SEP/NX，详见 [用户态](usermode.md)。第 6 章不新增 CPU 品牌、型号或拓扑采集，
这些沿原版第 8 章继续；也不启用 SIMD、五级分页或多核。

## 地址经过哪些变换

| 地址 | 意义 | 当前实例 |
| --- | --- | --- |
| 逻辑地址 | 段信息和段内偏移 | 实模式 Loader 的段值与偏移；保护模式的选择子与偏移 |
| 线性地址 | 分段变换后的地址，交给分页机制 | 内核 `0xffff800000100000`、用户入口 `0x800000` |
| 物理地址 | 页表转换结果，供内存/设备访问 | Kernel 位于 `0x100000`，CR3 根位于 `0x101000` |

实模式通常按 `segment * 16 + offset` 计算地址；A20 关闭会使 bit20 回绕。
保护模式段寄存器中的值是选择子，CPU 用它索引 GDT/LDT，加载隐藏的基址、界限和访问权。
本项目选择平坦段，基址为 0；PG=0 时线性地址直接对应物理地址。
开启分页后，CR3 提供物理页表根，CPU 根据线性地址索引页表。
64 位子模式下普通 CS/DS/ES/SS 不再通过非零段基址平移地址；FS/GS 有独立机制，
本项目尚未实现 TLS 或每 CPU 数据。

当前四级页表把线性地址分为 PML4/PDPT/PD/PT 的四组 9 位索引和 12 位页内偏移。
初始 RAM 直映在 PDE 使用 PS=1 的 2 MiB 大页，转换在 PD 层结束；用户演示使用
4 KiB PTE，以便分别赋予代码 R-X、栈 RW-NX 权限。详见 [物理内存](memory.md)。

四级分页要求 48 位规范地址：bit63:48 必须复制 bit47，允许范围是
`[0, 0x00007fffffffffff]` 与 `[0xffff800000000000, 0xffffffffffffffff]`。
两者中间的数值不是规范地址。符合规范仍可能没有映射；页表存在也仍须检查权限。
内核高半区偏移 `0xffff800000000000` 是布局选择，CPL 与页表 U/S 才决定用户访问权。
高半区别名不会改变物理地址，也不能把它写进 CR3。

## 三种模式怎样连接

```text
BIOS → Boot / Loader：实模式，BIOS 中断读取 FAT12
    → 每扇区：PE=1 / CODE32 平坦复制 → CODE16 / PE=0 返回实模式
    → 实模式获取 E820 / VBE
    → CR0.PE=1，远跳转到 CODE32：保护模式，PG=0
    → CR4.PAE=1 → CR3=0x90000 → EFER.LME=1
    → CR0.PG=1：IA-32e 激活，EFER.LMA=1，旧 CS 仍是兼容子模式
    → 远跳转到 CODE64（L=1、D=0）：64 位子模式，执行 head.S
    → CR3=0x101000 → 内核 GDT / 远返回：高半区代码与独立栈 → Rust
```

实模式便于使用 BIOS，但普通 16 位段偏移限制了内核搬运范围。
第 6 章基线使用 big/unreal mode：短暂置 PE，为 FS 加载平坦段，清 PE 后借用隐藏缓存搬运。
这不是 IA-32e 兼容模式。第 7 章第一部分已改为每扇区的受控保护模式窗口，详见 [启动](boot.md)：
BIOS 负责实模式低端读盘，平坦保护模式负责复制，再经 16 位代码段回到实模式。
当前路径不再依赖 FS 缓存跨 BIOS 调用保持。

正式切到保护模式时，先 LGDT、置 CR0.PE，再远跳转加载 CODE32。
PE 开启保护机制，远跳转更新 CS 隐藏属性；此后代码不再调用实模式 BIOS。
进入 IA-32e 必须先在 PG=0 时准备 PAE、物理页表根和 LME，最后开启 PG。
LME 是软件请求，LMA 是 CPU 报告的激活状态；只写 LME 不会立刻开始执行 64 位代码。
IA-32e 包含兼容与 64 位两个子模式，当前 CS.L 才决定是哪一种，64 位代码段要求 D=0。

head.S 切换页表时，新旧页表都必须覆盖当前代码、栈以及将跳入的高半区目标。
否则写 CR3 后下一条取指就可能缺页。页表根按物理地址加载，远返回使 RIP 到达
高半区链接地址；BSS 清零并建立独立栈后才调用 Rust。
内存初始化稍后删除低地址别名，用户演示再显式建立受限用户页，不共享全部内核映射。

## Rust 怎样核对当前状态

`main.rs` 在安装异常入口之后、初始化内存之前调用 `processor::verify_boot_mode()`。
它不写控制寄存器或 MSR，也不增加映射；失败则沿现有 panic 路径诊断并停机。

| 读取内容 | 通过条件 | 说明 |
| --- | --- | --- |
| CR0 | PE=1、PG=1 | 保护机制与分页已启用 |
| CR4 | PAE=1、LA57=0 | 当前引导使用四级分页 |
| IA32_EFER（0xc0000080） | LME=1、LMA=1 | 已请求且已激活 IA-32e |
| CS 与 LAR | CS=0x08；P/S/代码/L=1，D/DPL=0 | GDT 中当前代码段配置为 64 位 ring0 |
| CR3 地址部分 | 0x101000 | head.S 固定的内核 PML4 根 |
| RIP / RSP | 高半区且符合 48 位规范地址规则 | 从真实 RIP 相对标签和栈寄存器取值 |
| RFLAGS | IF=0 | 仍在单核初始化阶段 |

LAR 查询当前选择子对应的描述符访问权，ZF=1 表示查询成功；读取成功后才使用返回值。
它读取的是描述符表属性，不能声称直接读取到了 CS 的隐藏缓存。
本项目 head.S 在 LGDT 后远返回重载 CS，随后只写 TSS 槽、不改代码段，因此二者保持一致。
EFER、当前指令执行与 RIP 取样共同支撑模式判断，不能单独拿高半区符号地址当执行证据。

当前检查发生在用户页配置之前，NXE/WP 由后面的用户入口启用，因此这里不要求它们已置位。
检查能确认进入 Rust 后的状态，不能替代 Loader 在模式切换前的能力检查；
也没有逐级遍历页表、验证任意 GDT 动态修改、实模式中间现场或五级分页运行。

位域与转换规则依据 [Intel 软件开发手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)
第 3A 卷的保护模式、分页和 IA-32e 初始化，以及第 2 卷的 LAR 指令。
运行命令见 [构建](../development/build.md)，实测结果见 [验证记录](../development/validation.md)。
